# 城市肌理 CityTexture · 产品需求文档（PRD）

> 版本：v2.0（重写：地理精确性优先）
> 日期：2026-10-14
> 背景：本产品将作为 MakerMuse 平台的「城市肌理」场景上线。作者在创想三维（Creality）实习，此为内部产品，**无需差异化叙事**。
> 范围：仅「城市」主题。

---

## 0. 一句话定位

输入一个城市 / 地址 / 一句描述，输出一份**地理上真实、可激光切割**的城市肌理或地标剪影 SVG——**路网走向、街区形状、地标位置与真实地图一致**，并能被激光机精确切出来。

---

## 1. 核心目标与原则

### 1.1 北极星目标

**「生成结果与真实地理的一致性」** 是本产品压倒一切的第一指标，高于「好看」「情绪」。

### 1.2 三条铁律（贯穿所有功能）

1. **地理真实优先**：凡涉及路网、街区、地标位置，必须来自真实地图数据（OSM/路网矢量），不靠 AI 脑补。
2. **AI 只做「表达」，不做「事实」**：AI 负责风格化、构图、可制造性约束的翻译；地理事实一律由确定性数据源供给。
3. **可制造闭环**：所有输出必须过 DFM 检查，产出激光机直接可切的 SVG。

---

## 2. 产出形态矩阵（三个模式）

| 模式 | 输入 | 内容来源 | 精度目标 | 适用场景 |
|---|---|---|---|---|
| **A 地图肌理（精确）** | 城市 / 地址 / 行政区 | OSM 真实路网+街区+水系 | 街道走向、街区形状、相对位置与真实地图一致 | 主推模式，也是「城市肌理」的默认 |
| **B 地标场景（精确）** | 一句含地标的描述 / 地名 | Wikimedia 检索 + 真实地标 + 生图 | 地标轮廓可识别，忠于真实建筑 | 「我想念悉尼歌剧院」类输入 |
| **C 写意剪影（情绪）** | 一句情绪化描述 | 参数化生成器 / 生图 | 风格自洽、可制造，不承诺地理真实 | 兜底 + 情绪入口 |

> 三者不是替代关系，是**分层**：用户给了精确地点 → A/B 精确模式；用户只给了情绪 → C 写意兜底。系统应自动判定走哪条，并让用户可手动切换。

---

## 3. 功能需求

### 3.1 模式 A：地图肌理（P0，最高优先级）

**输入**
- 城市名（中/英）、地址、或行政区。支持坐标（lat,lng）作为兜底。
- 可选参数：范围（半径 / 固定框）、比例尺、图层取舍（路网 / 街区 / 水系 / 建筑轮廓）。

**处理链路（全确定性，无 AI 事实）**
```
输入地点 → 地理编码(Geocoding) 得到经纬度+边界框
→ OSM/Overpass 拉取真实矢量：道路(highway)、街区边界(landuse/boundary)、水系(waterway/water)、建筑(building)
→ 投影到目标画布（毫米坐标系，等比）
→ 道路分级（主干道/次干道/支路 → 不同线宽，对齐激光可切的线宽下限）
→ 街道=划线(蓝)、街区轮廓=雕刻(黑)、水系=雕刻(黑)、切割外框=切穿(红)
→ DFM 检查（线宽、孔间距、包络）→ SVG
```

**精度验收标准（硬指标）**
- 主干道路网走向、交叉口位置与真实地图叠加误差 ≤ 1%（画布尺度下肉眼不可辨）。
- 道路层级：主干道/次干道/支路至少 3 级区分，线宽差 ≥ 0.5mm 且 ≥ 设备最小线宽。
- 生成的 SVG 内嵌真实地理元数据（中心坐标、bbox、OSM 数据时间戳），可溯源。

**关键技术依赖（本次新增，见第 6 节）**
- 地理编码：Nominatim（OSM 官方）。
- 矢量数据：Overpass API。
- 投影：Web Mercator → 画布毫米坐标的确定性映射。
- 道路简化：Douglas-Peucker 简化到「激光可切且不失辨识度」的分辨率。

### 3.2 模式 B：地标场景（P0）

**输入**：一句含真实地标的描述，或地名（如「悉尼海港边的歌剧院」「埃菲尔铁塔」）。

**链路（现有城市木刻师路线，精度加强）**
```
ReAct Agent 标准化 → Wikimedia 中英双路检索真实地标(确认存在+取英文名)
→ 生图（激光友好约束，prompt 明确要求「忠于真实建筑轮廓特征」）
→ Potrace 矢量化 → DFM → SVG
```

**精度加强点（相对旧版城市木刻师）**
- 检索结果需返回地标的**结构化特征**（高度、轮廓、标志性结构），写进生图 prompt，提升可识别度。
- 增加「地标校验」环节：生成后可用参考图做轮廓相似度粗检（P1，可选）。
- 明确不支持「组合多个地标」「虚构建筑」——与真实地标库强绑定。

### 3.3 模式 C：写意剪影（P1，兜底）

- 复用现有参数化天际线生成器（按城市名确定性哈希）。
- 定位：当用户输入无法解析出精确地点/地标时的兜底，且前端明确标注「写意，非真实地理」。
- 不承诺地理真实，但必须可制造。

### 3.4 制造保障：DFM（P0，三模式共用）

- 6 项确定性检查（包络、切割线宽、矢量线宽、孔径、孔间距、安全边距），阈值取设备∩材料交集最严值。
- 设备库对齐创想三维 Falcon 系列全机型（内部数据源，比黑客松 demo 的 3 台更全）。
- 输出 SVG 内嵌 `<metadata>` 溯源块：中心坐标、数据来源、生成时间、DFM 结果。

### 3.5 交付与交互

- **格式**：SVG 为主（mm 单位、分层：红切穿/蓝划线/黑雕刻）。预留 DXF 导出（P1）。
- **交互范式**（对齐 MakerMuse 场景规范）：情绪化 landing → 多步向导 → 上传/输入带好坏示例 → 预览 → 下载。详见配套文档《MakerMuse 调研与接入建议》。
- 隐私：地址门牌号不写入文件；分享卡默认脱敏。

## 4. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 模式 A 地图拉取+生成 ≤ 15s（Overpass 有超时/缓存）；模式 B ≤ 30s；模式 C 秒出 |
| 可靠性 | 所有外部依赖（地理编码/Overpass/LLM/生图）失败均有降级；A 降级到「城市边界轮廓」，B 降级到 C |
| 数据合规 | OSM 数据需遵守 ODbL 授权（署名 + 衍生数据共享），接入前法务确认 |
| 成本 | Overpass/Nominatim 免费但需自建缓存（公共实例有速率限制）；生图按次计费需限流 |
| 可观测性 | 地理数据命中率、Overpass 超时率、DFM 首过率、AI 成本按模式打点 |

## 5. 技术方案与复用清单（给产研团队交接）

### 5.1 可直接复用（黑客松已验证）

| 模块 | 作用 |
|---|---|
| `lib/image-gen.ts` | Qwen-Image 生成+编辑，激光友好 prompt 约束 |
| `lib/potrace-vectorize.ts` | 像素图 → 闭合复合矢量路径 |
| `lib/deepseek.ts` | OpenAI 兼容 JSON 调用 + 字段校验 + 兜底 |
| `lib/dfm.ts` | 6 项制造检查（逻辑复用，设备库替换为内部 Falcon 全机型） |
| `lib/photo-vectorize.ts` | Otsu 二值化 + 连通域（照片类兜底） |
| `app/api/*` ReAct 调度 + 降级模式 | 场景/照片链路的调度骨架 |

### 5.2 必须新增（本次核心，demo 完全没有）

| 模块 | 说明 |
|---|---|
| **地理编码层** | Nominatim 接入：地址/城市名 → 坐标 + bbox |
| **矢量数据层** | Overpass API：拉取 highway/landuse/waterway/building |
| **投影与简化层** | 经纬度 → 毫米画布投影；Douglas-Peucker 道路简化 |
| **道路分级规则** | highway 标签 → 3 级线宽映射（对齐 DFM 线宽下限） |
| **数据缓存** | Overpass/Nominatim 结果缓存，避免重复请求公共实例 |

### 5.3 已知技术债（demo 遗留）

- serverless 下 `request.signal` 异常，需独立 `AbortSignal.timeout`。
- potrace/jimp 需声明 `serverExternalPackages`。
- 函数时长上限 120s（模式 A 的 Overpass 大范围请求可能接近，需分块/缓存）。

## 6. 风险与开放问题

1. **OSM 数据覆盖不均**：小城市/非西方城市路网可能稀疏或缺失 → 需定义「数据不足」的降级策略（退到城市边界轮廓 + 提示）。
2. **ODbL 授权义务**：OSM 衍生数据需署名共享，接入前法务必须确认（这是模式 A 最大的合规风险）。
3. **「尽量精确」的天花板**：激光切割的物理约束（最小线宽、孔间距）决定了路网不能无限精细，需在「地理精确」和「可制造」之间明确取舍规则（主干道保留、支路按阈值裁剪）。
4. **地标相似度**：文生图对真实地标的还原度有上限，模式 B 的「可识别」需用户测试标定。
5. **Overpass 公共实例稳定性**：生产需自建 OSM 数据镜像或购买商业路网服务，避免公共 API 限流影响体验。

## 7. 里程碑

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| M1（3–4 周） | 模式 A 全链路：地理编码 + Overpass + 投影 + 道路分级 + DFM + SVG | 任一主要城市能生成与真实地图一致的路网 SVG |
| M2（1–2 周） | 实机验证：Falcon 实切路网稿 + 地标稿，标定线宽/孔径阈值 | 「切得出来 + 认得出」有照片证据 |
| M3（1 周） | 合规：OSM ODbL、隐私政策、地标版权清单 | 法务通过 |
| M4（2 周） | 模式 B/C 接入 + MakerMuse 场景范式 UI 改造 + 分享闭环 | 沙箱跑通三模式 |
| M5 | 上线 | 北极星「地理一致性」有基线 |

## 8. 成功指标

- 北极星：**生成结果的地理一致性验收通过率**（人工抽样 vs 真实地图叠加）。
- 过程：路网数据命中率、DFM 首过率、各模式分流占比、单次生成 AI/数据成本。
